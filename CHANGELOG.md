## [Unreleased]

### Added

- Repository setup: agent documents (`AGENTS.md`, `docs/agents/`), coding standards, evidence standards, ship rules, pull request and issue templates, and community files.
- Plugin skeleton: `paseo-plugin.json` declaring `requirements.paseo` as `>=0.10.1 <0.11.0`, the Paseo version the smoke test targets (`0.10.1`), a strict TypeScript package, one entry module, and a test folder with a smoke test.
- One narrow host port: `server/host.ts` is the interface hook handlers use to reach Paseo, `server/paseo-host.ts` is the only module that imports the Paseo SDK, and `test/support/fake-host.ts` is the fake adapter that lets handlers be tested without a daemon.
- Harness descriptors: `harness/claude.json` holds every agent-specific fact (config directory variable, skills directory and mode, MCP delivery), `shared/harness.ts` is the field table, `server/harness.ts` loads the folder, and two checks fail when a descriptor breaks the contract or source code names an agent id.
- Resume marker: a ticket agent Paseo resumes gets its ticket marker again when its session opens (`beforeSessionOpen` on the host port, `agent.session_open` in the adapter), by its title or labels; when neither can be read it stays unmarked and one line is logged.
- Lifecycle relay: a ticket agent's turn end, pending permission, creation and archive reach its orchestrator as a message, held while the orchestrator's own turn runs, so supervision needs no heartbeat. The port gained `isRunning`; the texts live in `server/messages.ts`.
- Composer pill: each agent's composer gets a pill that counts what waits for the user (a ticket agent's open request counts toward its orchestrator, the stream agent's toward itself) and hides at zero. The port gained `onPermissionResolved` and `serveWaitingCount`; the pill's texts live in `client/pill-text.ts`. Checkpoints stay Paseo's native `AskUserQuestion`: no custom card.
- Git guard: a ticket agent's `git push`, `git checkout` and other branch-moving git are refused by a Node hook script (`guard/git-guard.mjs`, run from `hooks/hooks.json`), only where `MWP_ROLE=ticket` is set; a `beforeCreate` handler sets it for agents titled `[Wave N] <NN> ...`, so the orchestrator keeps its git. The harness descriptor gained the `guard` field (`hook` or `path-shim`), and the port hands `beforeCreate` the agent's title.
- One version token: the version lives in `package.json`, and a check fails, naming both files, when `.claude-plugin/plugin.json`, `.claude-plugin/marketplace.json` or the contract version (`CONTRACT_VERSION` in `shared/contract.ts`) differs from it, or when `package.json` names the package differently from the Paseo id in `paseo-plugin.json`, or the marketplace entry differently from `plugin.json`. The two Claude Code manifests are new, so this repository loads as a Claude Code plugin, named `matt-with-paseo-plugin` (the Paseo id stays `matt-with-paseo`) so it can be enabled beside the skills repository's plugin, and `hooks/hooks.json` can take effect.
- Sandbox capability: the harness descriptor gained the `sandboxed` field (`true` or `false`), stated for every agent and required by the contract test; `harness/claude.json` says `true`. Nothing reads it yet, since no code routes work by harness and no screen shows one.
- Role identity: a role is read from the agent's labels (`wave` and `ticket` for a ticket agent, `stream` for the stream agent) through one helper, `shared/role-labels.ts`, which the relay and the waiting count now share, and from the env marker inside the agent; the plugin registers no provider per role, and a check fails when its code calls the SDK's provider API. A hand-started agent still needs a provider of its own.
- Situational instruction on the event: every message the plugin sends an agent ends with a `Next:` line naming the moves open to its reader, the four relay messages (by outcome for a turn end, by kind for a request) and the git guard's refusal; `combine` keeps one `Next:` line at the end of a held message. A check fails when a message type lacks the line.
- Plain words on screen: `client/pill-text.ts` holds a plain label for each term of the skills' words blocks (`PLAIN_LABELS`), and a check fails when a text the pill shows, or a literal in another client file, uses a precise term without its plain label. The precise terms stay in `server/messages.ts` and the README's development sections. The first release draws no card, so the pill is the one screen covered.
- Human words reach the orchestrator: what a person types in a ticket agent's chat is told to the orchestrator that owns it, ahead of the turn end in the same message (a `Human words:` text with the ticket, the agent and the message ids, never their text). The orchestrator's own prompts are told apart by `clientMessageId` (`server/human-words.ts`); the smoke test confirms it on a real host. The orchestrator's report listing them is the skills' part, in `hanh9898/matt-with-paseo`.
- Cheap sensor: at a ticket agent's turn end the plugin checks the conditions in `sensor/conditions.json`, one at a time, against the turn's outcome and timeline, and sends its orchestrator a `Stall suspected:` message (with a `Next:` line) only when one is flagged, so the orchestrator's stall judgement reads a transcript for that case alone. The `off-task` condition is a named slot for a small model, with none wired. No eval case yet: this repository's Claude Code plugin holds no skill an eval prompt could reach.
- Gate cap: concurrent gates are capped at a share of the machine's processors, half by default, adjusted by `MWP_GATE_SHARE` (`shared/gate-cap.ts`). When more ticket agents of one orchestrator run than the cap allows, the plugin sends the orchestrator a `Gate cap passed:` message (with a `Next:` line) telling it to queue the ready tickets; holding the spawns is the skills' part, in `hanh9898/matt-with-paseo`. The plugin stops no spawn and no shell command itself.
- Cost levels: `presets/cost-levels.json` holds the Cheap, Balanced and Max presets, each setting the agent and model of the stream, wave and ticket roles on top of Paseo's own profiles, which the plugin never creates, edits or deletes. `MWP_COST_LEVEL` picks a level and `MWP_COST_<ROLE>` (`agent/model`) overrides one role (`shared/cost-levels.ts`). Offering the levels in setup is the skills' part, in `hanh9898/matt-with-paseo`.
- State outside the repository: `shared/state-location.ts` names the per-user directory where the plugin keeps what must persist (`MWP_STATE_DIR` moves it) and the one marked block it may write in a repository's `AGENTS.md`; `server/state.ts` is the one module that writes a file, refusing names that leave the directory. Nothing persists yet: the README lists each holder of in-memory state. A check fails when any other module imports a file-writing API or a process API. The wave files stay in the integration branch's checkout, by the user's decision on #12.
- Release checklist: `docs/agents/release-checklist.md` orders the routine step for a new Paseo minor: read its changelog, run the smoke test on it, then widen `requirements.paseo` the same day with the upper bound no tighter than the evidence requires. A check fails when the item, its order after the smoke run or a pointer to the file is missing.
- CI on three systems: `.github/workflows/ci.yml` runs `npm ci`, `npm run typecheck` and `npm test` on `ubuntu-latest`, `macos-latest` and `windows-latest`, only for pushes to `release/v*` branches and pull requests from them into `main`, so it runs at the milestone run and on no stream's ship pull request. No pre-commit hook, Husky or Prettier is added; the pre-commit decision waits until after milestone `v0.5.0`. Running the drift check on every commit stays with `hanh9898/matt-with-paseo`, by the user's decision on #17.
